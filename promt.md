### АРХИТЕКТУРНЫЕ ТРЕБОВАНИЯ И СТАНДАРТЫ КОДА

1. **Архитектурный шаблон**: Domain-Driven Design (DDD). Раздели проект на домены в папке `app/Domains`:
   - `Domains/Auth` (Пользователи, Роли, Профили)
   - `Domains/Catalog` (Анализы, Категории)
   - `Domains/Laboratories` (Лаборатории, Рабочие часы, Слоты времени)
   - `Domains/Orders` (Корзина, Заказы, Платежи, Статусы)
   - `Domains/Results` (Результаты анализов, Генерация PDF, Шифрование медицинских данных)
2. **Строгая типизация**: `declare(strict_types=1);` в каждом PHP файле. Никаких типов `mixed` без крайней необходимости. Возвращаемые типы обязательны для всех методов.
3. **Бизнес-логика**: Вынесена в `Action`-классы (подход Single Responsibility). Никакой логики в Контроллерах, Livewire-компонентах или Filament-ресурсах. Они только принимают ввод и вызывают соответствующие Actions.
4. **Безопасность (HIPAA / GDPR / ФЗ-152)**:
   - Персональные данные пользователей и результаты анализов в БД должны храниться в зашифрованном виде (используй Laravel `AsEncryptedCollection` или `encrypted` касты для чувствительных полей).
   - Разграничение прав на базе Spatie Permission (Роли: Super Admin, Lab Assistant, Patient).
   - Защита от SQL-инъекций через Eloquent Parameter Binding, строгая валидация входящих DTO (Data Transfer Objects).
5. **Оптимизация производительности**:
   - Предотвращение N+1 запросов с помощью strict-режима в Eloquent: `Model::preventLazyLoading(!app()->isProduction())`.
   - Кэширование тяжелых запросов каталога (Redis / Memcached).
   - Индексы базы данных: составные, индексы для полнотекстового поиска (PostgreSQL `tsvector` или Laravel Scout/Meilisearch в перспективе).
6. **Очереди и асинхронность**: Все ресурсоемкие задачи (отправка писем, генерация PDF-отчетов, синхронизация статусов с внешними API) должны выполняться через очереди (`Queueable`, `ShouldQueue`).

### ЧАСТЬ 1: ПОДРОБНАЯ СХЕМА СУБД (МИГРАЦИИ, СВЯЗИ, ИНДЕКСЫ)

Сгенерируй код миграций со всеми ограничениями целостности, внешними ключами (`foreignId`), каскадными операциями, мягким удалением (`SoftDeletes`) и необходимыми индексами.

#### 1.1 `users` & `profiles`
- `users`: `id`, `email` (unique, index), `password`, `remember_token`, timestamps.
- `profiles` (для ПДн): `id`, `user_id` (FK, cascade), `first_name` (encrypted), `last_name` (encrypted), `middle_name` (encrypted, nullable), `phone` (unique, index), `birth_date` (date), `gender` (enum: male, female), timestamps.

#### 1.2 `laboratories` & `laboratory_working_hours`
- `laboratories`: `id`, `name`, `address` (string), `is_active` (boolean, index), timestamps.
- `laboratory_working_hours`: `id`, `laboratory_id` (FK, cascade), `day_of_week` (unsignedTinyInteger 0-6), `open_time` (time), `close_time` (time), `slot_interval_minutes` (integer, default 15), timestamps.

#### 1.3 `categories` & `analyses`
- `categories`: `id`, `parent_id` (FK, nullable, для вложенных категорий), `name` (string), `slug` (unique, index), `is_active` (boolean, default true), timestamps.
- `analyses`: `id`, `category_id` (FK, restrict), `name` (string), `slug` (unique, index), `sku` (string, unique, артикул), `description` (text), `preparation` (text, правила подготовки), `biomaterial` (string, тип биоматериала), `price` (decimal 12,2), `lead_time_days` (unsignedInteger), `is_active` (boolean, default true, index), `is_popular` (boolean, default false, index), timestamps, softDeletes.
- *Добавь FULLTEXT индекс на `name` и `description`.*

#### 1.4 `orders`, `order_items`, `order_statuses` (State Machine)
- `orders`: `id`, `user_id` (FK, restrict), `laboratory_id` (FK, restrict), `order_number` (string, unique, index), `appointment_datetime` (datetime, index), `total_price` (decimal 12,2), `payment_status` (enum: pending, paid, refunded), `current_status` (enum: new, processing, ready_for_lab, analyzing, completed, cancelled), `payment_id` (string, nullable, для эквайринга), timestamps, softDeletes.
- `order_items`: `id`, `order_id` (FK, cascade), `analysis_id` (FK, restrict), `price` (decimal 12,2, фиксация цены), `discount` (decimal 12,2, default 0), timestamps.
- `order_status_histories`: `id`, `order_id` (FK, cascade), `status` (string), `changed_by_user_id` (FK, nullable), `comment` (string, nullable), timestamps (история изменения статусов для аудита).

#### 1.5 `medical_results` (Результаты анализов)
- `medical_results`: `id`, `order_item_id` (FK, cascade, один результат на позицию заказа), `lab_assistant_id` (FK, null, кто заполнил), `parameter_values` (jsonb - зашифрованные показатели, например `{"hemoglobin": {"value": 145, "unit": "g/L", "reference": "120-160"}}`), `pdf_path` (string, nullable, путь к защищенному файлу на S3/Storage), `verified_at` (datetime, nullable), timestamps.

### ЧАСТЬ 2: БИЗНЕС-ЛОГИКА И ПАТТЕРНЫ (ACTIONS & SERVICES)

Реализуй следующие классы-сервисы и экшены:

1.  **CartService (Интерфейс + Реализация)**:
    - Хранение корзины в Redis/Сессии с привязкой к сессии гостя или ID пользователя при авторизации (автоматическое объединение корзин при логине).
    - Методы: `add(Analysis $analysis, int $quantity = 1)`, `remove(int $analysisId)`, `updateQuantity(int $analysisId, int $quantity)`, `clear()`, `getItems()`, `getTotal()`.
2.  **OrderCreationAction**:
    - Принимает `CheckoutDTO` (user_id, laboratory_id, appointment_datetime, list of analysis_ids, payment_method).
    - Выполняет транзакцию базы данных (`DB::transaction`).
    - Проверяет доступность выбранного слота времени в лаборатории (блокировка слота от Double Booking через `select ... for update`).
    - Создает запись `Order`, переносит товары из `CartService` в `OrderItems` с фиксацией цен.
    - Инициирует событие `OrderCreatedEvent`.
3.  **MedicalResultVerificationAction**:
    - Принимает ID результата анализа и массив значений.
    - Проверяет права текущего пользователя (только Lab Assistant / Admin).
    - Генерирует PDF-документ с результатами на фирменном бланке (используй обертку под `Barryvdh\DomPDF\Facade\Pdf` или аналогичную).
    - Загружает файл в приватное хранилище `Storage::disk('secure_medical_results')`.
    - Меняет статус соответствующего `OrderItem` и всего заказа (если все позиции готовы) на `completed`.
    - Отправляет уведомление пациенту по Email/SMS (через очередь) с защищенной одноразовой ссылкой на скачивание.
